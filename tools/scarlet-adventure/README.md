# 红魔馆冒险布置

本目录记录红魔馆的冒险内容源、复现工具和原生测试夹具。用户允许挖掘、搭建和自由选择路线；不设置禁止破坏区域或强制顺序。

## 游戏行为

- **远古铁装备**：头盔、胸甲、护腿、靴子、剑、镐、斧、锹、锄、长矛，共十件。沿用对应原版铁装备的属性、耐久和铁锭修理，不继承下界合金的防火、韧性或击退抗性。无新增廉价升级配方。
- **陈设转换**：仅处理原稿中的 34 个盔甲架，开启手臂，保留原有姿势；四件护甲以及主副手中的下界合金武器、工具换为对应远古铁物品，剩余耐久严格处于 70%–88%。原稿实际有 136 件护甲，手持槽原本为空。旧架子迁移后打一次性标记，玩家后来放入的装备及其他位置的盔甲架不参与转换。
- **宝藏**：补给 8、守卫 6、隐藏 3、主藏 1、图书馆 1，共 19 处（13 木桶、6 箱）。视线可达的未开容器在近处显示档位色粒子，准星对准后显示名称。地下图书馆的七曜研究箱位于 **4902 1005 7134**，保底一册附魔书、一张记录火球、泡泡或叶片的弹幕形状图纸和弹幕核心。每个存档共享一次奖励，开箱、破坏、漏斗取物、重载和建筑修复都不会补发。
- **女仆妖精**：33 个守卫点，玩家进入 56 格内、与刷新点高度相差不到 5 格时激活。刷怪避开距玩家 10 格以内的位置，12 格局部范围最多 4 只女仆，每秒最多新增 4 只遭遇怪。每个点绑定实际实体 UUID，游走或卸载会保留该身份。
- **牢房**：按原稿铁门和可站立空间核实 197 个囚禁点，覆盖五层的 394 扇铁门下半部；其中 49 个可营救。部分外沿大囚禁厅按成对门划分关押位置，并不宣称它们是完全隔开的独立房间。
- **营救**：可救哥布林有绿色可见名称，不主动攻击玩家；实际打开/拆除门或挖通原有围墙后，它会寻路离开关押范围。离开后记录获救、停止该点刷新，并提供一次少量铜钱谢礼。敌对囚犯释放、囚犯被驯服时同样停止该点补充。
- **补刷**：死亡记录释放对应点位；玩家需要连续离开该楼层附近至少 18 分钟，返回后才有机会缓慢补充。守在现场不会重复刷新。营救、释放、驯服完成的点永久退休。脚下与头部必须为空气，不放宽全维度自然刷怪条件；和平难度不生成遭遇怪。

未靠近楼层的囚犯暂停 AI。奖励和女仆点在所属区块完成建筑写入和实体加载后启用。囚禁点继续检查相邻区块，避免在门墙未就绪时处理牢房。

## 数据流和修改边界

1. 建筑的最终 NBT 位于 `common/src/main/resources/data/reverie_dreams/structure/gensokyo/scarlet_devil_mansion.nbt`。
2. 冒险配置保存在该 NBT 的 `reverie_adventure` compound，按 GensokyoAdventure Codec 编辑。survey_layout.py 仅导出候选到本地 .agent/workspaces/scarlet-survey，不覆盖正式配置。
3. Fabric datagen 生成 gensokyo_adventure 与 gensokyo_structure_metadata JSON，统一注册表负责资源重载，生成器不再加工建筑。
4. 装备模型、物品定义、中文名称、标签、穿戴资源定义及战利品表均走已有 datagen provider。运行时资源位于 `common/src/generated/resources`。
5. `GensokyoStructureGeneration` 在 FEATURES 完成建筑方块，并把四个新增箱纳入同一分块索引。`ScarletAdventure` 在服务器线程维护容器、旧架转换、遭遇和营救；`ScarletAdventureState` 使用维度 SavedData 保存一次性状态。

当前目录以 NONE 旋转、比例 1、原点 **4810 1004 7046** 的正式红魔馆选址为依据。修改该选址、比例或目录版本之前需要重新审查房间和冒险迁移策略。地图高度、河流、群系、revision 不属于本轮修改。

新生成建筑自动应用。旧版存档不会自动重铺建筑；必要时由用户显式执行已有命令：

```mcfunction
/touhou gensokyo repair reverie_dreams:scarlet_devil_mansion
```

这条命令通过结构维护系统重新铺设选区，保留同类型容器库存和已领取奖励的账本。冒险版本 2 的新增女仆与奖励提示会直接随代码和资源载入。旧箱已被领取、被玩家改作他用，或所在区块不具有建筑安装标记时，先检查原因再决定是否修复几何。

## 美术来源

2026-11-20 后续返修：用户指出护甲物品图标混素，第一版四张图标已替换为真正的 16×16 母版，使用 6–7 种有组织的冷灰铁色阶。导出脚本现在直接读取 `art/native_16x16/`，不再缩小旧大图；详见 `art/README.md` 和 `data/ancient-iron-icons-16-20261120/comparison.png`。穿戴 UV 与工具图没有改变。下述原生实机截图来自返修之前，不能作为新版四件库存图标的实机验收；新版已做原尺寸及整数倍浅深槽离线查看，用户验收待定。

`art/generated/` 保存内置 ImageGen 的 13 张生成原稿：十件装备库存图标、长矛手持图和两张人形穿戴 UV。不是手工调亮原版贴图。提示词要求保留原版轮廓/UV，以石墨深色、偏冷铁灰、克制银色高光形成较亮的铁系列，不增加发光、符文或噪点。

`export_generated_textures.py` 将生成稿颜色导出到引擎原生像素尺寸，并用原版 alpha 轮廓约束透明边界和穿戴接缝；此步骤是格式适配。图标 16×16、长矛手持图沿用原版尺寸、穿戴 UV 64×32。`data/scarlet-adventure-20261119/equipment-review.png` 为像素放大总览，最终美术认可由用户决定。

## 验证与复现

- `validate_layout.py` 独立检查生成目录与 provider 输入一致、站立净空、地面、围墙、门覆盖和宝藏位置。
- `tools/gensokyo-buildings/validate_template.py data/scarlet-adventure-20261119` 独立逐项比较原稿与生成 NBT，只允许本次授权的装备替换和开启手臂差异。
- `review_plan.py` 输出五层牢区和入口层平面图，以及包含全部世界坐标的 `world-points.json`。
- `native/` 是 Fabric 原生实际游戏夹具，检查铁属性、铁砧、34 架、双手旧架迁移、无关玩家架、宝箱耗尽、牢房覆盖、真实寻路营救、补刷冷却、repair 和保存重开。它会在一次性测试世界有界加载红魔馆；这不是正式游戏强制加载逻辑。
- `ScarletEquipmentVisualTest` 使用单独的日光平台核对原版与新甲的正背面、双手和第一人称武器显示。正面图左侧为远古铁，背面图右侧为远古铁。

最终原生冒险运行通过 1,964 条断言，另有无遮挡美术截图与 NeoForge 编译通过证据。详见 `data/scarlet-adventure-20261119/verification.md`；这不代表用户已经认可新外观，也不代表额外做过双客户端、DH/C2ME 或 Polymer 运行测试。

本轮不涉及 Polymer，不运行 Polymer 测试；不构建正式安装包，不更新 `build/dist`。运行测试环境及临时构件必须在验证后清理。精简证据放在 `data/scarlet-adventure-20261119/`，运行日志/清理记录放在本地 `.agent/`。
